## Runtime campaign artwork

When image generation is enabled, the service generates a fresh campaign image for any approved feature. The client never maps feature IDs to static artwork and never accepts a model URL. Current/candidate records may carry an opaque descriptor `{id,width,height,bytes,mime}`; legacy records without an image still render unchanged. Image campaigns use one approximately247×231px canvas, full-canvas artwork and a large24–28px accessible HTML hook. New payloads select a finite `composition`: `poster`, `split` or `image-led`; old image records default to `poster`. Poster uses a solid upper type block and lower hero with a bottom-left pill CTA. Split protects the left53% for type/CTA and shows a strongly right-aligned image. Image-led uses dominant upper artwork, an opaque lower headline plate and top-left pill CTA. The image prompt follows these zones; solid type plates and CTA pills guarantee text contrast independently of generated negative space. Model output cannot provide presentation code. Compact campaigns show no explanatory body paragraph: the claim message remains as the labelled region’s accessible description. Optional scenario/items remain in a closed native disclosure outside the canvas. Admin previews use the same sized canvas with claim/scenario/format review metadata outside it. Long legacy/pathological hooks grow naturally instead of clipping; parent actual desktop/mobile checks establish final geometry for the chosen sample.

JPEG bytes come only from authenticated same-origin `GET /api/advertising/image?id=<48-lowercase-hex>`, through the shared request generation, cancellation and 15-second timeout boundary. MIME/size are checked against JPEG/4MiB. PHP admits enabled current images for members and candidate images for administrators. The displayed Home pair uses a session-memory Blob URL across SPA navigation; its successor is staged off-screen and browser-decoded before publication handoff. A stays visible and retains its URL while eligible B loads; B image404/decode failure keeps eligible A until a later successful read. Redux retains metadata only; no image bytes, URLs, base64 or private state enter browser storage. Session-generation middleware revokes URLs on logout/account change, eligibility invalidation and publication replacement. Staged URLs are revoked when a newer request/session supersedes them. The hook aborts unmounted requests and rejects late results across session changes; temporary administration preview URLs revoke on unmount/replacement. Metadata-read failures immediately hide the spotlight until a successful safety read;401/password-change failures clear the advert and its private URL. This is distinct from successor-image failure following a successful eligibility read. On first load no incomplete image/copy pair is published. Admin artwork failures retain their bounded fallback frame.

The existing administrator draft exposes a nonempty allowed-composition list, maximum headline words2–8(default5), image enablement, allowed model, quality, image planning complexity, square/landscape size, timeout, visual style/brief length, estimated USD reservation and daily/monthly image counts. Image planning complexity is independent of output quality. Image usage is displayed separately from text tokens. Images API output has no token ceiling: reservations and estimated currency budgets are not guaranteed invoice caps. Unknown outcomes retain reservations and pause work. Prepare has a finite 375-second browser deadline to cover the PHP image-inclusive execution envelope; ordinary reads remain 15 seconds. No client view initiates generation.

Automatic generation/publication uses one existing interval or daily schedule. Administration defaults interval entry to minutes (0.5minutes persists exactly30seconds;3minutes180seconds); daily time/IANA timezone remain unchanged. Turn manual approval off for automatic publication. The backend rotates eligible services according to configured weights and cycles enabled layouts; the browser does not choose/generate paid campaigns.

Local overnight execution is now owned by Windows Task Scheduler's **The Allin Family - Local Advertising**, independently of the chat. It starts at Gary's logon and recovers exited worker/engine/callback processes. Gary must remain logged in; AC-only idle-sleep prevention allows display-off and releases on battery. See [local supervisor operations](../../api/bin/local-advertising/README.md) for status, enable/stop and limitations. The main local API/Vite remain separate.

Short campaign CTA labels and canonical service identifiers live in the existing fixed destination map. Shopping uses `Open list`; library games use `View game` and still navigate to their detail panel, without installing or launching a game. Legacy text cards retain their descriptive labels. CTA safety revalidation, live publication handoff and all image-session controls are unchanged.
